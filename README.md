# 生徒会執行部タスク管理システム

生徒会執行部などの組織で、チームごとのプロジェクトとタスク、期限、資料を1か所で確認・更新するためのWebアプリです。Googleスプレッドシートを保存先にし、Google Apps Script で動かします。

> **English summary:** A task management web app for student councils and similar organizations. Data is stored in your own Google Spreadsheet, and the app runs on Google Apps Script. It requires a Google Workspace organization account. The UI is in Japanese.

- 現在の版: **v1.5**(2026-10-25)。変更の経緯は「更新履歴」を参照してください。
- ライセンス: [MIT License](LICENSE)

> **注意:** 個人が作成したサンプル実装です。特定の組織の公式システムではありません。導入する場合は、導入する組織の判断と責任で行ってください。

## 開発経緯

岡山県内の高校生が暇つぶしで作ったら生徒会長に採用されました。

## 機能
 
- **ホーム**: チームごとのタスク件数、期限超過、進行中プロジェクトの進捗。表示の「自動 / ライト / ダーク」切り替え。
- **班別一覧**(チームごとの一覧): タスクとプロジェクトを追加できます。末尾の「班なし」タブは、どのチームにも属さない単発タスクの一覧です。
- **班なしタスク**: どのチームにも属さない単発のタスク。全員が作成でき、「取り組む」を押した人が担当者になります(担当は1人だけ)。
- **プロジェクト**: 状態(進行中 / 完了 / 保留)ごとの一覧と、詳細(説明・進捗・タスク一覧)。
- **タイムライン**: 「全体 / チームごと」の絞り込み。期限超過・期間外の警告つき。
- **自分のタスク**: 自分が担当のタスク。
- **タスクの並び替え**: 各ページのタスク一覧(班別一覧・班なし・プロジェクトのタスク一覧・自分のタスク)で、行をドラッグして自分の見やすい順番に並び替えられます。順番は本人の画面だけに反映されます。
- **アーカイブ済みのタスク**: 班別一覧・班なし・自分のタスクの下にある「アーカイブ済みのタスク」から、全員が見られます。資料一覧にも、アーカイブ済みのタスクの資料が表示されます。
- **資料**: 4区分(全体 / チーム全体 / プロジェクト / タスク)の資料を、チーム → プロジェクトの順に開閉して見られます。追加・削除・検索ができます。
- **管理**: メンバー・チーム・役割の管理、チームリーダーによるメンバーの編成、アーカイブの確認と元に戻す。
- **会議モード**: 文字を大きくします。
- **実行中表示**: 保存や削除の間は「実行中…」を出し、画面の操作を止めます。
## 動作環境
 
- **Googleスプレッドシート** と **Google Apps Script**(ランタイム: V8、タイムゾーン: Asia/Tokyo)
- **Google Workspace のアカウント**(組織のドメイン)。公開範囲を「ドメイン内の全員」にする前提のため、個人のGmailアカウントでは、この設定での運用はできません。
- **ブラウザ**: 最新の Google Chrome を推奨します。動作確認はChromium系ブラウザで行いました。
- 利用者は、専用のソフトをインストールする必要はありません。主にPCでの利用を想定しています。
## 導入に必要な権限
 
- **スプレッドシートの作成**と、そのシートに紐づく **Apps Script の編集・実行**ができること(導入する人)。
- Apps Script の初回実行時に許可を求められる内容は次のとおりです。
  - このスプレッドシートの読み書き(`spreadsheets.currentonly`: 開いているシートだけ)
  - ログインしているユーザーのメールアドレスの取得(`userinfo.email`: 誰が操作したかの確認に使います)
- **ウェブアプリとしてのデプロイ**: 実行ユーザーは「自分」、アクセスできるユーザーは「ドメイン内の全員」にします。
- 導入後の運用には、デプロイした本人のアカウントが必要です(「運用上の注意」を参照)。
## 初回導入時の注意
 
- **必ず、新規作成したテスト用のスプレッドシートで動作確認をしてください。** 既存の業務用シートには導入しないでください。
- ダミーデータ(`seedDummy`)は、テスト用シートだけで実行してください。
- 本番で使うときは、テスト用とは別の新しいスプレッドシートを作り、ダミーデータを入れずに `setup` を実行します。
- 「ドメイン内の全員」への公開ができるかは、導入前に実機で確認してください。
## セキュリティ
 
### データの保存先と通信
 
- データは、導入者が作成したスプレッドシートにだけ保存されます。
- このコードは、外部のサーバーへデータを送信しません(外部への通信処理を含みません)。
- 利用者は、Googleアカウントでログインして使います。
### アクセスの制御
 
- **登録されたメンバーだけが操作できます。** メンバーとして登録されていないアカウントは、データを見ることも操作することもできません。
- 権限の確認は、画面で隠すだけでなく、サーバー側(`Code.gs` の `api()`)ですべて行っています。
- 公開範囲は「ドメイン内の全員」です。ドメイン外の人は、ウェブアプリを開けません。
### 導入者が決めること
 
- **シートの共有範囲**: スプレッドシートは、管理者だけに共有してください。チームのメンバーに、シートの直接編集をさせないでください。画面を通さない編集は、権限チェックを通らないため、データが壊れたり権限を外れたりする原因になります。
- **デプロイの管理**: デプロイしたアカウントの名義で動きます。そのアカウントを管理者2〜3名で共有し、引き継ぎ方法を決めてください。
- **テスト用の機能**: 「代行表示」(`DEV_MODE` / `DEV_IMPERSONATE`)は、本番では設定しないでください。
### 公開するときの注意(このリポジトリを使う人へ)
 
- **個人情報を載せないでください。** 実際のメールアドレス、氏名、所属、スプレッドシートのID、デプロイしたURLを、コード・README・Issue・スクリーンショットに含めないでください。ダミーデータのメールアドレスは `example.com` のものだけです。
- **セキュリティ上の問題を見つけた場合**は、公開のIssueに書かないでください。GitHub の「Security」タブから、非公開で報告してください。
## 制限事項(未実装・既知の制約)
 
- **ポイント機能は未実装です。** 班なしタスクの「取り組む」は、記録として残すだけです。
- **メール通知、カレンダーとの連携は未実装です。**
- **提案と承認、完了報告・2段階承認・差し戻し、期限変更申請、「重要」の指定は未実装です。**
- 他のシステム(既存のスプレッドシートなど)との連携はありません。
- タスクのドラッグ並び替えは、タッチ操作(スマートフォン・タブレット)に対応していません。
- 操作は1つずつ順に処理されるため、同時に操作が多いときは少し待つことがあります。
- 実際の Apps Script・組織のアカウントでの動作は、導入する人が確認する必要があります。

## セットアップ(最初は必ずテスト用のシートで)
 
1. Google Workspace のアカウントで**新しいスプレッドシート**を作る(既存シートには触れません)。
2. 「拡張機能 → Apps Script」を開き、`Code.gs` と `Index.html`(HTMLファイル、名前は `Index`)の内容を貼り付ける。
3. 「プロジェクトの設定」で「appsscript.json マニフェスト ファイルをエディタで表示する」をオンにし、`appsscript.json` を貼り付ける。
4. 関数 `setup` を実行して権限を許可する。必要なシートが作られ、実行した人が「システム管理者」として登録されます。
5. **テスト用シートだけ**: 関数 `seedDummy` を実行すると、ダミーのメンバー・チーム・プロジェクト・タスク・資料が入ります(データがあると実行を拒否します)。
6. 「デプロイ → 新しいデプロイ → ウェブアプリ」で、実行ユーザー=自分、アクセスできるユーザー=「ドメイン内の全員」にしてデプロイする。
7. 発行されたURLを開き、管理画面でメンバーのメールアドレスを登録する。
## 更新を反映する手順
 
1. `Code.gs` と `Index.html` を、**両方**新しい内容に置き換える(片方だけだと画面とサーバーが食い違います)。
2. 「デプロイ → デプロイを管理 → 編集 → バージョン: 新バージョン」でデプロイし直す。コードを保存しただけでは、公開中のURLには反映されません。
3. 関数 `setup` を実行する(列が増えた版のときは必須。実行しても既存のデータは消えません)。
`setup` が必要になった版: v1.1(「資料リンク」に `区分`・`対象ID`)、v1.3(「班」に `アーカイブ`)、v1.6(新しいシート「タスク並び」)。v1.5 は不要でした。
 
## 権限
 
役割は、画面に表示される名前のままにしています(会長、システム管理者、班長、班員)。チームは画面上の「班」にあたります。
 
| 操作 | 会長・システム管理者・先生 | 班長 | 班員 |
|---|---|---|---|
| 全チームの閲覧 | ○ | ○ | ○ |
| タスク・プロジェクトの作成/編集(説明欄を含む) | ○(全チーム) | ○(全チーム) | ○(全チーム) |
| タスク・プロジェクトのアーカイブ/元に戻す | ○(全チーム) | ○(自チーム) | 不可 |
| ステータスの更新 | ○(全チーム) | ○(自チーム) | 自分が担当のみ |
| 班なしタスクの作成・編集、「取り組む」 | ○ | ○ | ○(登録メンバー全員) |
| 班なしタスクの「取り組みをやめる」 | ○(誰の分でも) | 本人のみ | 本人のみ |
| 班なしタスクのアーカイブ/元に戻す | ○ | 作成者のみ | 作成者のみ |
| 資料の追加・削除 | ○ | ○ | ○(登録メンバー全員、区分を問わない) |
| チームのメンバーの追加・削除 | ○(全チーム) | ○(自チーム。班長の任命・解任は不可) | 不可 |
| チームの追加・名称変更・アーカイブ/元に戻す、メンバー登録、全体権限、班長の任命 | ○ | 不可 | 不可 |
 
- **先生**は、会長・システム管理者と同じく、すべての権限を持ちます(全チームの操作、メンバー・チーム・役割の管理を含む)。「全体権限」シートに `先生` として登録します。管理画面の「全体」の欄で任命できます。
- アーカイブ済みのチームでは、タスク・プロジェクトの作成/編集/状態更新はできません(資料の追加と削除はできます)。
- 担当者は、そのタスクのチームに所属するメンバーから選びます。
- 「副会長」の役職は廃止しました。「全体権限」シートに「副会長」の行が残っていても無視されます(削除して構いません)。
## 班なしタスクと「取り組む」
 
どのチームにも属さない単発のタスクです。チームのタスクとは次の点が違います。
 
- **作成**: 登録メンバー全員が、「班別一覧 → 班なし」または追加フォームの担当班で「班なし」を選んで作成できます。プロジェクトには入れられません。作成時に担当者は選べません。
- **取り組む**: タスク詳細の「取り組む」を押すと、押した人が担当者になります。1つのタスクにつき担当者は1人だけで、すでに担当者がいるときは押せません(同時に押された場合も、先に処理された1人だけが担当者になります)。
- **取り組みをやめる**: 担当者本人と会長・システム管理者・先生が行えます。やめると、状態は「未着手」に戻り、再び募集中になります。完了したタスクは、取り組むことも、やめることもできません。
- **状態の更新**: 取り組んでいる人と会長・システム管理者・先生。
- **編集(説明欄を含む)と資料の追加・削除**: 登録メンバー全員。
- **アーカイブ/元に戻す**: 作成者と会長・システム管理者・先生。
- **記録**: 誰がいつ取り組んだか、やめたかは、「担当者」シートと「操作ログ」(「タスクに取り組む」「タスクの取り組みをやめる」)に残ります。将来、取り組んだ人にポイントを付ける仕組みを足すための土台です。**ポイントに関する機能は、まだ一切ありません。**
- 班なしタスクの担当班の欄は空欄です。シートを手で編集するときも、空欄のままにしてください。
## 資料の区分
 
資料は4つの区分で登録できます。資料ページの「資料を追加」からも、タスク詳細からも追加できます(タスク詳細からは「タスク」の区分)。
 
- **全体 / チーム全体 / プロジェクト / タスク**。区分を問わず、登録メンバー全員が追加・削除できます。
- 削除は、「削除」ボタンを押したあと、表示が「もう一度押すと削除」に変わるのでもう一度押すと実行されます。
- タスクとプロジェクトを新規作成するときは、フォームの「資料」欄で、資料名とURLをいくつでも一緒に登録できます(任意)。1件でも不正な行があると、何も作成されません。編集のときは資料欄は出ません(資料ページかタスク詳細から追加します)。
- 同じURLは、同じ区分・同じ対象の中で重複して登録できません。
- 資料ページは、チーム → (チーム全体 / プロジェクト / 単発タスク) の順に、クリックで開閉するプルダウンです。開いた状態は操作しても保たれます。
- 資料ページ上部の検索欄は、資料名・URL・追加者・チーム名・プロジェクト名・タスク名を対象に、空白で区切った語をすべて含む資料を探します。
- 「資料リンク」シートの `区分` と `対象ID` で、どこの資料かを決めます。区分が空欄の古い行は、タスクの資料として扱われます。
## アーカイブ済みのタスクの見方
 
- アーカイブしたタスクは、全員が見られます。班別一覧・班なし・自分のタスクの下にある「アーカイブ済みのタスク」を開き、行を押すと詳細が開きます。
- アーカイブ済みのタスクは、状態の変更・編集・取り組むはできません。元に戻せるのは、これまでと同じ人(班長、班なしタスクは作成者、会長・システム管理者・先生)です。
- 資料の追加と削除は、アーカイブ済みのタスクでもできます。資料ページでは、各班の「アーカイブ済みのタスクの資料」にまとまります。検索の対象にも入ります。
## タスクの並び替え
 
- 各ページのタスク一覧で、行をドラッグして順番を入れ替えられます(班別一覧、班なし、プロジェクトのタスク一覧、自分のタスク)。
- 順番は一覧ごと・ユーザーごとに保存され、本人の画面だけに反映されます。ほかの人の並びは変わりません。
- まだ並び替えていないタスクは、期限の順で下に並びます。
- 順番は「タスク並び」シートに保存します。操作ログには記録しません。
- ドラッグ操作は、PCのブラウザで確認しています。スマートフォンなどのタッチ操作では動かないことがあります。
## 日時・表示
 
- タスクとプロジェクトの開始日と期限(終了日)は、それぞれ「時刻なし」または「時刻を指定」を選べます。時刻なしの期限は、その日の終わりまでとして扱います。保存形式は `yyyy-MM-dd` または `yyyy-MM-dd HH:mm` です。
- ホームの上部で、表示を「自動 / ライト / ダーク」に切り替えられます(このブラウザに記憶されます)。
- 資料のリンクは青の下線、区分の見出しは黒の太字で、色と形で区別します。
## チームのアーカイブ
 
管理者(会長・システム管理者・先生)が、管理画面から行います(確認のため、ボタンを2回押します)。
 
- アーカイブしたチームは、ホーム・班別一覧・プロジェクト・タイムラインなどから消えます。
- そのチームのタスク・プロジェクトは、作成・編集・状態更新・元に戻すができなくなります。
- 資料の追加と削除は、アーカイブ後も、チーム全体・プロジェクト・タスクのどの区分でもできます。資料ページの「アーカイブ済みのチーム」にまとまります。
- 管理画面から元に戻すと、すべて元どおりになります。
## データの扱い
 
- 日付・時刻はすべて文字列で保存します。シートを手で編集するときも、`yyyy-MM-dd`(または `yyyy-MM-dd HH:mm`)の形式で入力してください。
- 「アーカイブ」列: タスクは `task`(単独)/`project`(プロジェクトと一緒に)、プロジェクトとチームは `TRUE`。空欄なら通常表示です。
- すべての更新は「操作ログ」シートに記録されます(日時、操作者、操作内容、対象)。
- 「タスク並び」シート: 各ユーザーが並び替えたタスクの順番です(メールアドレス・一覧・タスクID・順番)。表示にだけ使い、手で編集しないでください。
- 重要フラグ・作成者・作成/更新日時の列は、後の段階(承認など)のために最初から持たせています。
## テスト用の「代行表示」
 
ロール別の見え方を確認するため、スクリプトプロパティに `DEV_MODE=1` と `DEV_IMPERSONATE=<メールアドレス>` を設定すると、システム管理者に限り、そのメンバーとして画面を確認できます(画面上部に「代行表示中」と出ます)。**本番では設定しないでください。**
 
## 運用上の注意
 
- デプロイしたアカウントの名義で動きます。そのアカウントが使えなくなると止まるため、スクリプトの編集権限は管理者2〜3名で共有し、デプロイの引き継ぎ手順を決めておいてください。
- システム用シートの共有は管理者に限り、テストにはダミーデータを使ってください。
- 画面が「読み込み中…」のまま止まるときは、`Index.html` を最新版に置き換えて新バージョンでデプロイし直し、シークレットウィンドウで開き直してください。

画面(`Index.html`)は、ブラウザで操作して確認しています。ただし、サーバー部分は模擬したものです。実際の Apps Script・組織のアカウントでの動作は、導入時に確認してください。
