# 生徒会執行部 タスク管理システム

生徒会執行部(11〜30人)が、各班のタスクと期限を1か所で確認・更新するためのWebアプリです。Googleスプレッドシート + Google Apps Script で動き、学校のGoogleアカウントだけで完結します。

- 現在の版: **v1.5**(2026-10-25)。変更の経緯は「更新履歴」を参照してください。
- 詳しい仕様は、設計書(別ドキュメント)にまとめています。

## 作成者

岡山県内の高校の生徒会執行部員が開発。Claudeで暇つぶしがてら作ってたら会長に採用されました。

## 機能

- **ホーム**: 班ごとのタスク件数、期限超過、進行中プロジェクトの進捗。表示の「自動 / ライト / ダーク」切り替え。
- **班別一覧**: 班ごとのタスク一覧。ここからタスクとプロジェクトを追加できます。末尾の「班なし」タブは、どの班にも属さない単発タスクの一覧です。
- **班なしタスク**: どの班にも属さない単発のタスク。全員が作成でき、タスク詳細の「取り組む」を押した人が担当者になります(担当は1人だけ)。
- **プロジェクト**: 状態(進行中 / 完了 / 保留)ごとの一覧と、詳細(説明・進捗・タスク一覧)。
- **タイムライン**: 「全班 / 班ごと」の絞り込み。班を選ぶとプロジェクトごとにまとまります。期限超過・期間外の警告つき。
- **自分のタスク**: 自分が担当のタスク。
- **資料**: 4区分(執行部全体 / 班全体 / プロジェクト / タスク)の資料を、班 → プロジェクトの順に開閉して見られます。追加・削除・検索ができます。
- **管理**: メンバー・班・役割の管理(会長・システム管理者)、班員の編成(班長)、アーカイブの確認と元に戻す。
- **会議モード**: 文字を大きくします。
- **実行中表示**: 保存や削除の間は「実行中…」を出し、画面の操作を止めます。

## セットアップ(最初は必ずテスト用のシートで)

1. 学校アカウントで**新しいスプレッドシート**を作る(既存シートには触れません)。
2. 「拡張機能 → Apps Script」を開き、`Code.gs` と `Index.html`(HTMLファイル、名前は `Index`)の内容を貼り付ける。
3. 「プロジェクトの設定」で「appsscript.json マニフェスト ファイルをエディタで表示する」をオンにし、`appsscript.json` を貼り付ける。
4. 関数 `setup` を実行して権限を許可する。必要なシートが作られ、実行した人が「システム管理者」として登録されます。
5. **テスト用シートだけ**: 関数 `seedDummy` を実行すると、ダミーのメンバー・班・プロジェクト・タスク・資料が入ります(データがあると実行を拒否します)。
6. 「デプロイ → 新しいデプロイ → ウェブアプリ」で、実行ユーザー=自分、アクセスできるユーザー=「(学校ドメイン)内の全員」にしてデプロイする。
7. 発行されたURLを開き、管理画面でメンバーのメールアドレスを登録する。

## 更新を反映する手順

1. `Code.gs` と `Index.html` を、**両方**新しい内容に置き換える(片方だけだと画面とサーバーが食い違います)。
2. 「デプロイ → デプロイを管理 → 編集 → バージョン: 新バージョン」でデプロイし直す。コードを保存しただけでは、公開中のURLには反映されません。
3. 関数 `setup` を実行する(列が増えた版のときは必須。実行しても既存のデータは消えません)。

`setup` が必要になった版: v1.1(「資料リンク」に `区分`・`対象ID`)、v1.3(「班」に `アーカイブ`)。v1.5 は列の追加がないため不要です。

## 権限

| 操作 | 会長・システム管理者 | 班長 | 班員 |
|---|---|---|---|
| 全班の閲覧 | ○ | ○ | ○ |
| タスク・プロジェクトの作成/編集(説明欄を含む) | ○(全班) | ○(全班) | ○(全班) |
| タスク・プロジェクトのアーカイブ/元に戻す | ○(全班) | ○(自班) | 不可 |
| ステータスの更新 | ○(全班) | ○(自班) | 自分が担当のみ |
| 班なしタスクの作成・編集、「取り組む」 | ○ | ○ | ○(登録メンバー全員) |
| 班なしタスクの「取り組みをやめる」 | ○(誰の分でも) | 本人のみ | 本人のみ |
| 班なしタスクのアーカイブ/元に戻す | ○ | 作成者のみ | 作成者のみ |
| 資料の追加・削除 | ○ | ○ | ○(登録メンバー全員、区分を問わない) |
| 班員の追加・削除 | ○(全班) | ○(自班。班長の任命・解任は不可) | 不可 |
| 班の追加・名称変更・アーカイブ/元に戻す、メンバー登録、全体権限、班長の任命 | ○ | 不可 | 不可 |

- アーカイブ済みの班では、タスク・プロジェクトの作成/編集/状態更新はできません(資料の追加と削除はできます)。
- 担当者は、そのタスクの班に所属するメンバーから選びます。
- 副会長の役職は廃止しました。「全体権限」シートに「副会長」の行が残っていても無視されます(削除して構いません)。
- 権限は画面で隠すだけでなく、`Code.gs` の `api()` 経由ですべてサーバー側で確認しています。

## 班なしタスクと「取り組む」

どの班にも属さない単発のタスクです。班のタスクとは次の点が違います。

- 作成: 登録メンバー全員が、「班別一覧 → 班なし」または追加フォームの担当班で「班なし」を選んで作成できます。プロジェクトには入れられません。作成時に担当者は選べません。
- 取り組む: タスク詳細の「取り組む」を押すと、押した人が担当者になります。1つのタスクにつき担当者は1人だけで、すでに担当者がいるときは押せません(同時に押された場合も、先に処理された1人だけが担当者になります)。
- 取り組みをやめる: 担当者本人と会長・システム管理者が行えます。やめると、状態は「未着手」に戻り、再び募集中になります。完了したタスクは、取り組むことも、やめることもできません。
- 状態の更新: 取り組んでいる人と会長・システム管理者。
- 編集(説明欄を含む)と資料の追加・削除は、登録メンバー全員。アーカイブ/元に戻すは、作成者と会長・システム管理者。
- 記録: 誰がいつ取り組んだか、やめたかは、「担当者」シートと「操作ログ」(「タスクに取り組む」「タスクの取り組みをやめる」)に残ります。将来、取り組んだ人にポイントを付ける仕組みを足すための土台ですが、**ポイントに関する機能は、まだ一切ありません**。
- 班なしタスクの担当班の欄は空欄です。シートを手で編集するときも、空欄のままにしてください。

## 資料の区分

資料は4つの区分で登録できます。資料ページの「資料を追加」からも、タスク詳細からも追加できます(タスク詳細からは「タスク」の区分)。

- **執行部全体 / 班全体 / プロジェクト / タスク**。区分を問わず、登録メンバー全員が追加・削除できます。
- 削除は、「削除」ボタンを押したあと、表示が「もう一度押すと削除」に変わるのでもう一度押すと実行されます。
- タスクとプロジェクトを新規作成するときは、フォームの「資料」欄で、資料名とURLをいくつでも一緒に登録できます(任意)。1件でも不正な行があると、何も作成されません。編集のときは資料欄は出ません(資料ページかタスク詳細から追加します)。
- 同じURLは、同じ区分・同じ対象の中で重複して登録できません。
- 資料ページは、班 → (班全体 / プロジェクト / 単発タスク) の順に、クリックで開閉するプルダウンです。開いた状態は操作しても保たれます。
- 資料ページ上部の検索欄は、資料名・URL・追加者・班名・プロジェクト名・タスク名を対象に、空白で区切った語をすべて含む資料を探します。
- 「資料リンク」シートの `区分` と `対象ID` で、どこの資料かを決めます。区分が空欄の古い行は、タスクの資料として扱われます。

## 日時・表示

- タスクとプロジェクトの開始日と期限(終了日)は、それぞれ「時刻なし」または「時刻を指定」を選べます。時刻なしの期限は、その日の終わりまでとして扱います。保存形式は `yyyy-MM-dd` または `yyyy-MM-dd HH:mm` です。
- ホームの上部で、表示を「自動 / ライト / ダーク」に切り替えられます(このブラウザに記憶されます)。
- 資料のリンクは青の下線、区分の見出しは黒の太字で、色と形で区別します。

## 班のアーカイブ

会長・システム管理者が、管理画面から行います(確認のため、ボタンを2回押します)。

- アーカイブした班は、ホーム・班別一覧・プロジェクト・タイムラインなどから消えます。
- その班のタスク・プロジェクトは、作成・編集・状態更新・元に戻すができなくなります。
- 資料の追加と削除は、アーカイブ後も、班全体・プロジェクト・タスクのどの区分でもできます。資料ページの「アーカイブ済みの班」にまとまります。
- 管理画面から元に戻すと、すべて元どおりになります。

## データの扱い

- 日付・時刻はすべて文字列で保存します。シートを手で編集するときも、`yyyy-MM-dd`(または `yyyy-MM-dd HH:mm`)の形式で入力してください。
- 「アーカイブ」列: タスクは `task`(単独)/`project`(プロジェクトと一緒に)、プロジェクトと班は `TRUE`。空欄なら通常表示です。
- すべての更新は「操作ログ」シートに記録されます(日時、操作者、操作内容、対象)。
- 重要フラグ・作成者・作成/更新日時の列は、後の段階(承認など)のために最初から持たせています。

## テスト用の「代行表示」

ロール別の見え方を確認するため、スクリプトプロパティに `DEV_MODE=1` と `DEV_IMPERSONATE=<メールアドレス>` を設定すると、システム管理者に限り、そのメンバーとして画面を確認できます(画面上部に「代行表示中」と出ます)。**本番では設定しないでください。**

## 運用上の注意

- デプロイしたアカウントの名義で動きます。そのアカウントが使えなくなると止まるため、スクリプトの編集権限は管理者2〜3名で共有し、デプロイの引き継ぎ手順を決めておいてください。
- システム用シートの共有は管理者と会長に限り、テストにはダミーデータを使ってください。
- 最初に実機で、学校アカウントでの「ドメイン内のみ」公開が可能かを確認してください(設計書の未決事項1)。
- 画面が「読み込み中…」のまま止まるときは、`Index.html` を最新版に置き換えて新バージョンでデプロイし直し、シークレットウィンドウで開き直してください。

## テスト

`node test/run.js` で、Apps Script を模擬した環境で `Code.gs` の動作を確認します(110件)。権限の許可/拒否、アーカイブの連動、時刻の入力チェック、資料の区分、班のアーカイブ、最後の管理者の保護などを含みます。画面(`Index.html`)は、ブラウザで実際に操作して確認しています。実際のApps Script・学校アカウントでの動作は、導入時に確認してください。
