# 生徒会執行部 タスク管理システム 第1版(MVP)

スプレッドシート + Google Apps Script のWebアプリです。仕様は設計書の12・14・15章(確定仕様)に従っています。

## ファイル

| ファイル | 内容 |
|---|---|
| `Code.gs` | サーバー側。認証、権限チェック、データの読み書き、操作ログ、セットアップ |
| `Index.html` | 画面(ホーム、班別一覧、プロジェクト、タイムライン、自分のタスク、資料、管理、会議モード) |
| `appsscript.json` | マニフェスト(ドメイン内のみ公開、必要な権限を最小限に指定) |
| `test/run.js` | 手元でのモック検証(`node test/run.js`)。権限の許可/拒否や主要操作を39件確認 |

## セットアップ(最初は必ずコピーしたテスト用のシートで)

1. 学校アカウントで**新しいスプレッドシート**を作る(既存シートには触れません)。
2. 「拡張機能 → Apps Script」を開き、`Code.gs` と `Index.html`(HTMLファイル、名前は `Index`)の内容を貼り付ける。
3. 「プロジェクトの設定」で「appsscript.json マニフェスト ファイルをエディタで表示する」をオンにし、`appsscript.json` を貼り付ける。
4. 関数 `setup` を実行して権限を許可する。必要なシートが作られ、実行した人が「システム管理者」として登録されます。
5. **テスト用シートだけ**: 関数 `seedDummy` を実行すると、ダミーのメンバー・班・プロジェクト・タスクが入ります(データがあると実行を拒否します)。
6. 「デプロイ → 新しいデプロイ → ウェブアプリ」で、実行ユーザー=自分、アクセスできるユーザー=「(学校ドメイン)内の全員」にしてデプロイする。
7. 発行されたURLを開き、管理画面でメンバーのメールアドレスを登録する。

## 第1版の権限

| 操作 | 会長・システム管理者 | 班長 | 班員 |
|---|---|---|---|
| 全班の閲覧 | ○ | ○ | ○ |
| タスク・プロジェクトの作成/編集/アーカイブ | ○(全班) | ○(自班) | 不可 |
| ステータスの更新 | ○(全班) | ○(自班) | 自分が担当のみ |
| 資料の追加 | ○ | 所属班のタスク | 所属班のタスク |
| メンバー・班・役割の管理 | ○ | 不可 | 不可 |

副会長は「全体権限」に登録できますが、第1版では閲覧のみです(設計書の要確認事項のため)。

権限は画面で隠すだけでなく、`Code.gs` の `api()` 経由ですべてサーバー側で確認しています。

## 設定とデータの扱い

- `Code.gs` 冒頭の `CFG.LEAD_CAN_EDIT_MEMBERS` を `true` にすると、班長が自班の班員の追加・外しをできます(プロトタイプの動き)。既定は設計書どおり `false`。
- 日付・時刻はすべて文字列(`yyyy-MM-dd`)で保存します。シートを手で編集するときも、この形式で入力してください。
- 「アーカイブ」列: タスクは `task`(単独)/`project`(プロジェクトと一緒に)、プロジェクトは `TRUE`。空欄なら通常表示です。
- すべての更新は「操作ログ」シートに記録されます。
- 重要フラグ・作成者・作成/更新日時の列は、後の段階(承認など)のために最初から持たせています。

## テスト用の「代行表示」

ロール別の見え方を確認するため、スクリプトプロパティに `DEV_MODE=1` と `DEV_IMPERSONATE=<メールアドレス>` を設定すると、システム管理者に限り、そのメンバーとして画面を確認できます(画面上部に「代行表示中」と出ます)。**本番では設定しないでください。**

## 運用上の注意

- デプロイしたアカウントの名義で動きます。そのアカウントが使えなくなると止まるため、スクリプトの編集権限は管理者2〜3名で共有し、デプロイの引き継ぎ手順を決めておいてください。
- システム用シートの共有は管理者と会長に限り、テストにはダミーデータを使ってください。
- 最初に実機で、学校アカウントでの「ドメイン内のみ」公開が可能かを確認してください(設計書の未決事項1)。
